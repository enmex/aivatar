# Анонимный AI Gateway

Node.js 22 + Express 5, PostgreSQL 17 и React-форма. Приложение и БД запускаются через Docker Compose. Node.js отдаёт и API, и собранный клиент на одном порту.

## Запуск

```sh
cp .env.example .env
```

Укажите в `.env` свой `AI_API_KEY`. По умолчанию используется OpenRouter и модель `openai/gpt-4o-mini`. У ключа должен быть доступ к выбранной модели. Можно заменить `AI_BASE_URL`, `AI_API_KEY` и `AI_MODEL` на параметры другого гейта с совместимым Chat Completions API.

```sh
docker compose up --build -d
docker compose logs -f app
```

Откройте **http://localhost:3000**. Форма сама создаёт анонимную сессию; регистрация не нужна. Если ключ ещё не задан, форма открывается, `/api/health` возвращает `aiConfigured: false`, отправка запросов недоступна.

```sh
docker compose down
```

Остановка не удаляет историю: Postgres хранит её в volume `postgres_data`. Команда `docker compose down -v` удаляет и БД, и историю.

## Настройка

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `AI_BASE_URL` | `https://openrouter.ai/api/v1` | Базовый URL без `/chat/completions` |
| `AI_API_KEY` | пусто | Ключ гейта; хранится только на сервере |
| `AI_MODEL` | `openai/gpt-4o-mini` | Идентификатор модели у выбранного гейта |
| `AI_TIMEOUT_MS` | `60000` | Максимальное ожидание ответа, 100–300000 мс |
| `AI_MAX_TOKENS` | `2048` | Лимит токенов ответа |
| `POSTGRES_DB`, `POSTGRES_USER` | `ai_gateway` | БД и пользователь |
| `POSTGRES_PASSWORD` | `local_dev_change_me` | Пароль БД; задайте свой перед публикацией |
| `PORT` | `3000` | Порт на хосте |
| `PUBLIC_ORIGIN` | `http://localhost:3000` | Разрешённый origin формы |
| `COOKIE_SECURE` | `false` | Установите `true` для HTTPS |

При смене внешнего порта измените также `PUBLIC_ORIGIN`, например `PORT=8080` и `PUBLIC_ORIGIN=http://localhost:8080`. После изменения `.env` выполните `docker compose up -d` для пересоздания контейнера приложения.

Compose публикует приложение на `127.0.0.1`; порт БД не публикуется. Для внешнего доступа используйте reverse proxy с HTTPS, укажите публичный `PUBLIC_ORIGIN` и `COOKIE_SECURE=true`. По умолчанию Express не доверяет `X-Forwarded-For`: за reverse proxy лимиты будут общими для адреса прокси. Настраивайте `trust proxy` под конкретную топологию перед публичным запуском, если нужны отдельные лимиты по клиентским IP. Лимиты хранятся в памяти одного процесса и сбрасываются при его перезапуске.

`POSTGRES_*` применяются при первой инициализации volume. Смена пароля в `.env` не меняет пароль в уже существующей БД.

## API

Все POST-запросы принимают `Content-Type: application/json`. Сессию определяет HttpOnly-cookie `ai_session`; передавать ID сессии в теле или URL не нужно. Токен cookie является секретом доступа к истории, а UUID сессии таким секретом не является.

| Метод | Путь | Результат |
| --- | --- | --- |
| GET | `/api/health` | Доступность БД и наличие настройки ключа ИИ |
| POST | `/api/sessions` | Создать сессию или вернуть существующую; тело `{}` |
| POST | `/api/sessions/new` | Создать новую сессию и заменить cookie; тело `{}` |
| GET | `/api/messages?limit=50&before=123` | Страница истории текущей сессии |
| POST | `/api/messages` | Отправить `{ "prompt": "Ваш вопрос" }` и получить ответ |

Пример:

```sh
curl -c /tmp/ai-gateway-cookies.txt \
  -H 'Content-Type: application/json' -d '{}' \
  http://localhost:3000/api/sessions

curl -b /tmp/ai-gateway-cookies.txt \
  -H 'Content-Type: application/json' \
  -d '{"prompt":"Объясни, что такое микросервис"}' \
  http://localhost:3000/api/messages

curl -b /tmp/ai-gateway-cookies.txt http://localhost:3000/api/messages
```

Ответ на отправку: `{ "turn": { "id": "1", "prompt": "…", "response": "…", "status": "completed", "model": "…", "error_code": null, "created_at": "…", "finished_at": "…" } }`.

История возвращает `{ "turns": [...], "nextBefore": "123" }`: записи внутри страницы идут от старых к новым. `nextBefore` передаётся как `before` для предыдущей страницы; `null` означает конец истории. `limit` — от 1 до 100. Идентификаторы записей передаются строками, чтобы не терять точность BIGINT в JavaScript.

Ошибки: `{ "error": { "code": "…", "message": "…" } }`. Основные статусы: `400` — неверные данные, `401` — нет активной сессии, `403` — чужой origin, `409` — запрос уже выполняется, `429` — лимит частоты, `502` — ошибка гейта, `503` — нет ключа, `504` — таймаут. Внутренние сообщения провайдера и ключи клиенту не передаются.

## Хранение и поведение

- Cookie действует 30 дней с создания сессии. В БД хранится SHA-256 токена, а не сам токен. SQL-запросы используют параметры.
- Таблица `sessions` хранит анонимные сессии; `chat_turns` — запросы, ответы, модель, время и статус `pending` / `completed` / `failed`. Миграции из `migrations/` применяются автоматически при старте под блокировкой PostgreSQL.
- Запрос сначала сохраняется как `pending`, затем отправляется провайдеру. Ошибки и таймауты сохраняются как `failed`. При аварийном завершении процесса зависшие запросы получают `request_interrupted` после истечения дедлайна; проверка выполняется при старте, каждые 30 секунд и при чтении истории.
- В одной сессии одновременно выполняется один запрос. Это ограничение обеспечивает уникальный частичный индекс Postgres и оно действует между экземплярами приложения.
- Модели передаются последние 20 успешных пар «вопрос–ответ», дополнительно ограниченные 48000 символами вместе с новым запросом. Это ограничение по символам, не точный подсчёт токенов. Максимальная длина запроса — 8000 символов.
- Перезагрузка страницы восстанавливает историю. Если запрос ещё выполняется, форма опрашивает историю каждые 2 секунды. Отключение браузера не отменяет запрос на сервере.
- Новая сессия меняет cookie и начинает пустую историю. Старые записи сохраняются в БД; восстановление старой cookie, удалённой cookie или истории с другого устройства через интерфейс не предусмотрено. Автоматическое удаление истории не настроено.
- Ответы возвращаются целиком, без стриминга. React отображает текст без исполнения HTML из ответа модели.
- Ограничения: 120 API-запросов в минуту, 20 отправок в минуту, 30 обращений к маршрутам сессии за 15 минут на IP.

## Проверки

Тесты адаптера гейта и конфигурации без БД и внешнего API:

```sh
npm test
```

Интеграционные тесты с отдельной временной БД в Docker:

```sh
docker compose -p ai-gateway-test -f compose.test.yml up --build --abort-on-container-exit --exit-code-from test
docker compose -p ai-gateway-test -f compose.test.yml down
```

В этих тестах реальный Postgres, а ответ ИИ заменён тестовым адаптером: ключ и платные запросы не нужны. Проверяются миграции, cookie, изоляция сессий, история после перезапуска API, пагинация, контекст, ошибки, конкурирующие запросы и восстановление зависших записей. Каждый запуск создаёт и удаляет собственную схему БД.

При наличии установленного Node.js и доступной тестовой БД:

```sh
npm install
TEST_DATABASE_URL=postgresql://user:password@localhost:5432/test npm run test:integration
npm --prefix client ci
CI=true npm --prefix client test -- --watchAll=false --runInBand
npm run build:client
```

Для локальной разработки задайте `DATABASE_URL` в `.env`, выполните `npm run dev` и в другом терминале `PORT=3001 npm --prefix client start`. Клиент на `3001` проксирует API на `3000`. Оставьте `PUBLIC_ORIGIN=http://localhost:3000`: встроенный прокси CRA заменяет заголовок `Origin` адресом бэкенда. Значение `http://localhost:3001` в этой конфигурации приведёт к отказу POST-запросов с кодом `403`. В Docker `DATABASE_URL` не нужен: Compose передаёт подключение через `PGHOST`, `PGUSER` и остальные переменные Postgres.

Зависимости сервера закреплены по прямым версиям. `package-lock.json` сервера будет создан после первого успешного `npm install`; включите его в репозиторий для фиксации транзитивных зависимостей. У клиента lock-файл уже есть.

Протокол подключения: [официальная документация OpenRouter Chat Completions](https://openrouter.ai/docs/api/api-reference/chat/send-chat-completion-request).
